# 舒尔特训练 · 设计说明与建议

## 一、关卡方案的一致性（种子化设计）

**同一关默认完全一致，且支持一键换版。**

每一关的完整方案——数字排布、格子底色、数字颜色与大小、方格的错落位置——全部由「关卡号 + 种子」经确定性随机（FNV-1a 哈希 + mulberry32）生成，不依赖任何服务端存储：

- 默认种子 = `hash("schulte:v2:{level}")`，因此同一关在任何设备、任何时候打开都是同一局面，成绩可公平比较，分享才有"挑战同一关"的意义；
- 游戏内「重新排版」按钮会生成一个新种子并重建整关方案，同时把种子写入地址栏（`?level=12&s=…`），分享这个链接即可把自定义局面原样发给别人；
- 成绩按关卡记录最好用时。

这样设计的原因：排布与配色对难度影响很大，固定方案下家庭成员之间、自己前后两次的成绩才有可比性；孩子重复挑战同一关时也能清晰感知进步。

## 二、关卡混合与难度曲线

方格与蜂巢**混合在同一个 1-500 关卡序列**中，不做单独筛选：每 3 关出现一个蜂巢关（第 3、6、9…关），其余为方格。等级只决定棋盘规模：

| 关卡 | 规模 | 段位 | 限时 |
| --- | --- | --- | --- |
| 1-3 | 3×3 | 入门 | 否 |
| 4-6 | 4×4 | 入门 | 否 |
| 7-25 | 5×5 | 入门→基础 | 否 |
| 26-45 | 6×6 | 进阶 | 否 |
| 46-70 | 7×7 | 高手 | 否 |
| 71-100 | 8×8 | 大师 | 否 |
| 101-110 | 8×8 | 骨灰 | 是 |
| 111-200 | 9×9 | 骨灰 | 是 |
| 201-350 | 10×10 | 地狱 | 是 |
| 351-500 | 10×10 | 传说 | 是 |

**限时规则（101 关起）**：按格子数给时间，每格可用时间从约 1.75s 随等级递减到 0.85s；HUD 首项切换为「剩余时间」倒计时，最后 10 秒红色脉冲告警；倒计时归零即挑战失败，弹窗展示已点进度，可重新挑战或换一套排版。暂停会同时冻结倒计时。

所有关卡默认解锁、可从任意关开始；通关后进度自动前进，"继续训练"按钮始终指向下一关。

### 扩展关卡（后续版本加关）

关卡不是逐关存储的数据，而是 (关卡号, 种子) 的纯函数结果；数据库按 `(uid, level)` 存档、没有关卡上限，因此**加关不需要任何数据迁移**，只需改一个文件——`packages/shared/levels.ts`（UI 与服务端共用的唯一来源）：

1. 调高 `MAX_LEVEL`；
2. 在 `LEVEL_BANDS` 末尾追加新段位（保持区间连续覆盖 1..MAX_LEVEL）；
3. 如需更大棋盘，在 `gridSizeForLevel` **末尾追加**新的规模档。

服务端的成绩校验、段位进度统计，以及 UI 的关卡列表、段位导航、"继续训练"全部自动跟随，无需改动。

两条稳定性红线：

- **不要改动已有的规模档阈值、形状规则和默认种子方案**（`canonicalSeed` 的 `schulte:v2` 前缀），否则老关卡的排布发生变化，历史最佳成绩失去可比性；
- 若确实要换生成方案，把种子前缀升级为 `v3` 另起一套：老成绩仍会保留，但两代方案的用时不再可比，单关榜会混合新旧成绩，上线前需明确接受这一点。

## 三、视觉生成规则

- **蜂巢**：整张棋盘渲染为一个 SVG，尖顶六边形按精确几何无缝拼接（行距 = 3/4 高度，奇数行右移半格），每片用描边 + 圆角连接，边界清晰且无重叠、无缝隙；
- **方格**：错落排布。格子在各自的网格区域内随机宽高（64%-98%）、随机对齐（左/中/右 × 上/中/下）、随机圆角，保证完整落在游戏区域内、互不重叠、不重复；
- **底色**：固定 5 种清新淡色（白、薄荷、浅杏、雾蓝、淡黄）随机组合；
- **数字**：固定 5 种低饱和深色（墨绿、赭橙、灰蓝、橄榄、绛红）随机上色，字号在 0.82-1.24 倍间随机；
- 所有随机都来自关卡种子，视觉丰富但每一关可复现。

## 四、计时与反馈设计

- 计时从第一次点按开始；HUD 常驻显示已用时间、当前数字/总数、失误次数、历史最佳；
- 只有点到正确的下一个数字才推进；点错：格子抖动 + 描边变红 + 低音提示 + 计数失误，不扣时间（后续可加"严格模式"：点错 +1s 罚时）；
- 点对的格子轻微弹跳后消隐，不留已点标记，减少扫视干扰；
- 暂停时棋盘数字整体隐藏，防止暂停偷看布局；
- 通关弹窗展示用时、失误、速度（秒/格）、历史最佳，并给出下一关/重玩/分享/返回四个明确出口。

## 五、分享直达

```text
https://<NAS地址>/app/fnos-app-schulte/?level=12
https://<NAS地址>/app/fnos-app-schulte/?level=12&s=3206784832   ← 换版后的自定义局面
```

前端启动时解析 `level` 与可选的 `s`（种子）参数并直接进入对局；默认局面不带种子参数，链接更干净。

## 六、家庭数据体系（已实现）与运营建议（路线图）

成绩与排行榜已接入 fnOS 用户体系，家庭成员互不占榜：

- **家庭成员身份**：通过统一网关 `X-Trim-UserId` / `X-Trim-UserName` 识别 NAS 用户，免额外登录；未经过网关的本机开发环境退回"本机玩家"体验身份；
- **服务端存档**：Nitro API + `node:sqlite`（Node 22 内置，免原生依赖），数据库文件放在包数据目录（`$STORAGE_DIR/schulte.db`），卸载时可随数据目录一并清理；浏览器 localStorage 保留为离线兜底与即时展示；
- **API**：`POST /api/records` 提交成绩并自动维护单关最佳；`GET /api/leaderboard`（总榜 / `?level=N` 单关榜）；`GET /api/me`（个人统计、各段位进度、最近成绩）；
- **家庭排行榜**：总榜按通关数与平均成绩排名、单关榜按最佳用时排名，前三名领奖台展示，单关榜可一键"去挑战"；
- **我的**：段位进度条、已通关/累计完成/近 7 天/平均成绩、最近成绩流水。

后续可演进为：

1. **训练报告**：近 7/30 天训练次数、平均速度曲线、各段位通过率，用简单折线图呈现（plays 表已留足字段）；
2. **每日挑战**：以日期为种子的固定关卡，全家同题竞技（种子机制已就绪，只需把日期混入种子）；
3. **家长控制**：限定孩子每日训练时长、锁定高段位关卡、查看孩子训练记录；
4. **数据导出**：CSV 导出成绩，配合卸载向导决定数据去留（模板已带数据目录约定）。

## 七、玩法扩展路线

引擎已把「形状 × 规模 × 皮肤方案」解耦，可低成本扩展：

- 倒序模式：从 N 点回 1；
- 字母/古诗模式：把数字换成字母或诗句顺序；
- 记忆模式：数字短暂显示后翻面，凭记忆按序点按；
- 双人竞速：同屏左右两半，同一关卡种子各点各的。

## 八、响应式策略

- 棋盘宽度取 `min(92vw, 58vh, 560px)`，横竖屏都能完整容纳；
- 格子字号随棋盘宽度和格数计算（`calc(width / k * 系数)`），3×3 到 8×8 都清晰可读；
- ≤760px 时 HUD 统计条换行占满整行、次要的"最佳"统计隐藏、首页关卡网格列宽收窄；
- 所有可点元素最小 38px 触控目标，棋盘做了 `touch-action: manipulation` 防止双击缩放；
- 遵循 `prefers-reduced-motion` 自动关闭动画。
